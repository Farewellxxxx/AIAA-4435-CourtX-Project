# 2026-11-10 复盘可读性改进

本次从 `169c80d` 开始，在 `feature/recap-playback` 上独立实现。交付目录为 `Windows_Recap`；此前三个程序目录未覆盖。

## 完成内容

- 按原场地尺寸绘制半场、禁区、罚球圈、三分线、篮筐和篮板。
- 六名球员和篮球按记录时间一起播放；有持球外圈、玩家白圈、球缝图标、近两秒轨迹和出手目标虚线。
- 播放/暂停、回到开头、0.5×/1×、时间轴和上一/下一出手。
- 所选出手与评语同步；出手前不会显示未来传球判断，防守上下文只引用该次出手之前的记录。
- 长文本按实际排版高度滚动，整段可选解说明确标注不随出手切换。默认依然是本地规则，没有接入 LLM 服务。

## 迭代与证据

1. 回放数据和选择逻辑：22 项检查，先复现 16 个失败，再全部通过。覆盖六人/球插值、重复时间戳、持球离散切换、起止点、无球回合、暂停/慢放和不修改原始记录。
2. 场景集成：10 项检查，先复现 5 个失败，再全部通过。确认复盘推进但实际球员与练习时钟不动，切换出手同步评语，重练生成新记录。
3. 可见窗口检查发现小窗口球场线偏移：原来的旋转枢轴未正确处理画布缩放。已改为在画布内组合线段变换，并用真实截图的边线覆盖检测回归。
4. 原有完整回归：规则 49、复审回归 9、场景 83、传接球 31、战术/控制 45、自由练习 28，共 245 项通过。

新增与原有测试合计 **277 项通过，0 失败**。两个真实窗口尺寸的边线图像检查均为 100% 可见覆盖。独立代码审查未发现 Critical、Important 或 Minor 问题，见 `recap-code-review.md`。

## 测试方式与边界

桌面自动操作工具两次初始化失败（`failed to write kernel assets`），备用桌面工具也出现相同故障。因此未把本次测试描述为人工点击试玩。使用额外编译符号 `COURTX_RECAP_REVIEW` 构建独立 QA 程序，调用实际场景与复盘接口，在真实可见窗口内捕获 IMGUI 和篮球图。QA 类不进入交付程序，打包时会检查最终程序集。

首次隐藏窗口录制未产生有效画面，已识别并放弃；可见窗口录制正常。长文本使用本地假解说提供者，以“长文本末尾检查标记”验证能滚动到底，没有发送网络请求。录像回放的是之前保存的真实练习记录，另外保留本次完整战术回归的场景录像。

记录约每 0.2 秒采样，播放时插值位置；这不是逐帧物理重演。轨迹仅显示最近两秒，虚线为目标方向。没有扩展投篮、计分或历史文件选择器。

## 实施决定

- 沿用已有 Unity 检出路径并创建新分支、独立程序目录；稳定分支和归档保留。代价：同一个源码目录不能同时显示两个分支。
- 按用户明确授权直接执行已确认设计，未再增加确认步骤；具体布局由实现者选择。
- 按用户要求保留证据和任务记录，代价是少量本地存储。
- 自动场景测试按真实时间等待复盘时钟。原 15 个离线帧只耗时约 0.013 秒，不能假定等于 0.5 秒；修改测试等待方式，没有改变实际播放速度。
- 桌面操作不可用时用独立 QA 窗口验证实际画面和状态；代价是没有逐个注入原生鼠标点击。正式程序的启动、压缩包完整性和稳定版保存均另行验证通过。
