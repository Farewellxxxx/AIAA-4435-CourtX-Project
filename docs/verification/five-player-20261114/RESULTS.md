# CourtX 5v5 · 验证记录

日期：2026-11-14。交付为 Windows 桌面原型，Unity 2022.3.62f3c1。

## 本轮实现

- 两个主要入口：战术板、即时回放。共用 FiveBoard/FiveCourtView/FiveRules，任意暂停时刻可拖动进攻或防守球员、撤销、返回原片段、单步、倍速和节点跳转。
- 中锋提中、后卫挡拆、牛角射手；三种整体 2–3 联防反应；代入角色与开局球权分别选择。
- 球员任务悬停显示，右侧保留攻防意图；掩护标记、2.5 秒渐细渐隐轨迹。
- 正常 5v5 第一人称练习：九个 NPC + 代入角色，正面眼睛、清晰号码；Q 立即传球、E 要球、C 再 call、V 归档回放。移除新入口中的读防守挑战；未添加 3D What-if。
- 真实记录独立保存，推演不覆盖原片段；终局编辑明确重新组织；分数时间再次编辑不改变之前的运动。

## 独立审查及修复

一次独立整分支审查，两个 P2，均已先复现失败、后修复并全量回归：

1. 已有假设在相邻帧间再编辑，会让之前的插值提前移动。现在用同时间的编辑前/后两帧记录瞬时断点，精确采样选择编辑后帧；连续拖动、同刻再次修改、撤销均覆盖。
2. 成功/失误终态仍然锁住规则运行。现在终态编辑从当前站位重新组织，丢球时明确恢复进攻方球权，空中传球保持位置及进度。

额外修复：独立构建材质裁剪导致初始化异常、球衣文字重叠、多次保存失败只保留最后一轮。保存失败用待存队列，提供全量重试。早期隐藏窗口截图失败属于测试启动方式，改为正常窗口后同一构建通过；失败日志保留。

## 实施决定与边界

- 原来的六人数据结构不硬改成十人：保留旧代码/场景，新增完整五人制路径；成本是两套旧新模块并存。
- 新记录使用 Replays5v5；旧 3v3 由旧程序读取，不凭空补球员。
- 源码在独立工作树，Unity 缓存和发布包放 E:，避免 C: 空间不足；未移动用户文件。
- 防守测试改为验证按职责响应：外线持球时允许低位守住区域，另测底线来球时低位启动；并非要求十人持续奔跑。
- 2D 视觉验收依赖新场景，与正常 3D 集成后一起执行，未提前宣称完成。
- 完整比赛计分、投篮、篮板、犯规及转换进攻不属于当前战术决策原型。
- 当前验证为桌面输入；头显/VR 控制器尚未验收。
- 3D What-if 按用户要求排除，开始练习始终使用预设。
- What-if 是临时分支，切换演练/回放或关闭时不保留；真实回合持久化。
- 防守反应是教学规则，不是经实战校准的预测概率。

无未处理的 Important/Critical；无需要延期记录的 Minor。用户真人学习效果和真实 VR 设备表现不由自动检查证明。
