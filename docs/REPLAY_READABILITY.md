# 2D 轨迹与复盘阅读优化

入口：`Windows_Readability/CourtX Learning.exe`。2026-11-12，本地分支 `feature/replay-readability`。旧 `Windows_LearningPolish` 保留，方便直接比较。

## 可以直接试的变化

- 球员近两秒轨迹使用明亮实线、窄深色边缘和屏幕像素线宽，较近片段更亮。小箭头提示实际移动方向，短到不够画箭头的路径不会硬加箭头。
- 青色为进攻、橙色为防守。点击球员圆标，只显示该球员的跑位轨迹；再次点击，或点球场上方的“显示全部”，恢复全部轨迹。其他球员的位置和篮球始终保留。切换记录或 A/B 时自动恢复全部。
- 金色实线显示记录中的空中球路；持球运球不再叠加一条金色尾迹。白色虚线箭头显示该次传球的出手目标。两条线含义不同。
- 球员圆标增加深色边缘，近距离时更容易分清。白圈仍表示你控制的角色，金圈仍表示持球人。
- 时间轴下方短线标出传球时刻，当前对应出手以金色突出；原来的拖动、播放、慢放与节点跳转继续可用。

轨迹仍只显示近两秒；如果选中的球员刚才一直站定，他可能没有可见尾迹。聚焦只影响显示，不切换操控角色、不改变战术或历史记录。记录按约 0.2 秒采样插值，画面不是逐帧重算物理。

## 验证

本次重新运行：教学目录/历史规则 79 项，学习生命周期 27 项，复盘规则 22 项，复盘场景 10 项，共 138 项，全部通过。

独立审核指出重叠球员的点击顺序问题：圆标互相遮挡时应选中实际显示在上层的球员。已用录制场景复现三条失败检查，再修正为按绘制顺序命中；六项专项检查覆盖重叠、缩放、留黑边、独立球员、空白和无记录。

修正后重新运行全部上述检查，144 项全部通过。发布程序使用真实鼠标验证了选取拥挤位置的 12、聚焦 01、再次点击及按钮恢复全部、时间轴点击/拖动，以及三条原有练习的历史读取。

独立 QA 程序采集 1024×576、1280×720、1920×1080、1280×800 四种尺寸，每种八个状态，共 32 张真实 Unity 截图。另有 64 项捕获与显示状态检查通过，包括命中坐标、切换记录清除聚焦、题目定格和不修改实战/回放事实。QA 使用录制示例作为显示夹具，不能作为用户练习或教学效果证据。

首轮隐藏启动时，1280×720 一组没有渲染，已记录为失败；重新从实际窗口启动后，32 张截图均通过非空检查。最终证据位于 `Preview/Playtests/Readability-20261112`，失败首轮另存 `round1`。检查最小窗口、宽屏与 16:10 布局；低于 1024×576 的尺寸不作已验证声明。

## 构建

- `LearningAuthoring.BuildReadability`：独立发布程序。
- `LearningAuthoring.BuildReadabilityQA`：带 `COURTX_READABILITY_REVIEW` 的截图检查程序，仅用于 QA。
- 仍使用 `TacticalTraining.unity` 和 Unity 2022.3.62f3c1，无新依赖。
- 原程序按 SHA-256 清单验证；用户原有回合只复制到新版本地 Replays，不放入分发压缩包。

最终程序哈希、原版本保留校验、原生鼠标验收及独立审核见 `docs/verification/readability-20261112`。
